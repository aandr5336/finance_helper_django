# 1.4. Аналіз контрольного прикладу

Типовий сценарій (користувач `demo` / `demo12345` після `seed_demo`).

| Крок | Дія | Сторінка / URL name | Скрін |
|------|-----|---------------------|-------|
| 1 | Відкрити сайт, увійти | `accounts:login` | Рис. 1.4.1 |
| 2 | Переглянути дашборд місяця | `budgeting:dashboard` | Рис. 1.4.2 |
| 3 | Список транзакцій + фільтр | `transaction_list` | Рис. 1.4.3 |
| 4 | Додати витрату | `transaction_create` | Рис. 1.4.4 |
| 5 | Деталі / редагування | `transaction_detail` / `update` | Рис. 1.4.5 |
| 6 | Категорії | `category_list` | Рис. 1.4.6 |
| 7 | Бюджет і прогрес | `budget_list` / `detail` | Рис. 1.4.7 |
| 8 | Ціль і поповнення (POST) | `goal_detail` + `goal_deposit` | Рис. 1.4.8 |
| 9 | Вихід analyst, вхід `analyst` | login | Рис. 1.4.9 |
| 10 | Огляд системи | `system_overview` | Рис. 1.4.10 |
| 11 | Той самий JOIN у Workbench | `sql/03_demo_queries.sql` | Рис. 1.4.11 |

Очікуваний результат: дані зберігаються в MySQL, дашборд оновлює суми, чужі записи недоступні для `demo`, analyst бачить зведення.
